# 音效识别抗噪调优（2.9.1）

## 问题

实战里“战斗声音一多就检测不到”。用 40 秒实战录像（视频音轨 + 人工标注事件）量化后确认：
**不是阈值问题，是分数先掉下去了。**

## 实测数据（闪避模板，9~11 个事件 / 40 秒）

| 方案 | 阈值 | 命中 | 非事件段误触发 | 非事件最高分 |
|---|---|---|---|---|
| 旧算法（窗长 0.5s + 整窗 RMS + 单帧） | 0.35 | 6/9 | 1 | 0.353 |
| 窗长=模板长 + 逐滞后 NCC + 连续2帧 | 0.28 | 8/9 | 2 | 0.433 |
| **窗长=模板长 + PHAT + 连续2帧** | **0.20** | **11/11** | **0** | **0.165** |

（最终这一轮把用户补充的两个事件也算进来：7.8s 是真实闪避但听不到声音、36.5s 是反击过程中的闪避音效）

反击模板：旧算法 2/2、非事件最高 0.111；新版 2/2、**非事件最高 0.053**，余量更大。

## 改了哪三处

1. **窗长 = 模板长度**（`sound.cpp: SndDetCreate`）
   原来 `win = max(模板长度, 0.5s)`，闪避模板只有 0.341s，窗里 47% 是无关声音。

2. **打分换成 PHAT（相位变换相关）**（`sound.cpp: detCompute`）
   ```
   R = X * conj(T) / (|X * conj(T)| + eps)   只保留相位结构
   score = max |ifft(R)|                     完全匹配 ≈1
   ```
   原来“整窗 RMS 归一化 + 峰值/窗长”在混战里会把模板那一段整体压小；
   PHAT 对音量和宽带噪声都不敏感，弱音效也能浮出来（最弱事件 0.176 → 0.283）。

3. **连续 2 帧确认**（`sound.cpp: SndDetFeed`）
   真实音效会持续 ≥2 帧（80ms/帧），单帧高分多半是偶发误报 → `consec >= 2` 才触发。

阈值（`soundhost.cpp`）：`SND_TH_DODGE 0.20`、`SND_TH_COUNTER 0.18`（旧值 0.35 / 0.25）。

## 注意：分数尺度变了

`SoundScore()` 现在返回 PHAT 峰值：**安静时≈0.000**（旧版 RMS 归一化时底噪 0.02~0.07），
事件时 0.3~0.9。以前根据“底噪 0.02~0.07”写的调参经验不再适用。

## 离线验证方法（下次改音效必须重跑）

```powershell
# 1) 从实战录像抽音轨（视频和人工标注时间点对齐才有意义）
ffmpeg -i 录像.mkv -vn -ac 1 -ar 32000 -c:a pcm_s16le video_audio.wav

# 2) 用改过的 sound.cpp 编离线台（sndtest.cpp 在 native/tools 里，链接 src\sound.cpp）
i686-w64-mingw32-g++.exe -O2 -o build\sndtest_new.exe tools\sndtest_offline.cpp src\sound.cpp

# 3) 跑逐帧打分，用 tools\eval_modes.py 对比人工标注事件
build\sndtest_new.exe video_audio.wav 闪避_自录.npy > frames.txt
```

`tools\` 里还有：
- `sndtest3.cpp`：可切 3 种打分方式（窗长/逐滞后 NCC/PHAT）做 A/B
- `eval_modes.py` / `eval_snd.py`：按人工标注算命中率、非事件分的 p95/p99/max
- `mix_snd.py`：把事件与噪声按不同 SNR 混音，测“失效点”
